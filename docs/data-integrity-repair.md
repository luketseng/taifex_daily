# 分鐘資料完整性：修正、驗證與歷史修復

本文整理 2026/10/27～10/28 完成的程式修正與正式資料修復。DB、原始報表、
憑證、日誌、備份與當次操作清單不隨文件提交；本文不提供可直接套用舊 rowid
的清理指令，也不代表其他部署環境已完成相同修復。

## 兩個獨立根因

### 重跑報表增加重複 K 棒

舊寫入流程假設首根為 15:01，並用固定第 839 根判斷夜盤終點。實際缺分鐘時，
該位置可能已落在後續日盤，造成舊夜盤資料未完全刪除，又插入同分鐘的新列。
刪除與插入還使用不同交易，插入失敗可能留下已刪除的資料。

例如一份 1,134 根的報表，舊流程重跑後會變成 1,431 列。同分鐘完全相同副本
會放大成交量；依固定筆數聚合多分鐘 K 棒時，也會讓分組錯位。

### tick 跨分鐘時遺失首筆成交

舊解析流程遇到新分鐘時，只結算上一分鐘與更新時間，沒有保留觸發切換的成交。
只有一筆成交的分鐘會整根消失；其他分鐘仍有 K 棒，但 Open、High、Low、Volume
可能錯誤。首次時間的開盤假設及收盤歸屬也需一起處理。

Git 至少在 2025/05/09 的 `dbc70a0` 已有此邏輯，之後搬入模組時仍保留。
這只能證明程式歷史，不能用來判定每個 DB 日期的匯入來源或受影響起點。

**原始 tick 內容相同不代表重複資料。**例如以下兩列是兩筆成交，必須全部保留：

```text
20261027,TX     ,202611     ,151744,46108,2,-,-,
20261027,TX     ,202611     ,151744,46108,2,-,-,
```

依既有報表 B+S 除以 2 的換算，該分鐘成交量貢獻為 `(2 + 2) / 2 = 2` 口。
DB 的「同分鐘重複 K 棒」與原始 tick 的「相同成交列」不可混為一談。

## 修正後的行為

| 路徑 | 行為 |
|---|---|
| `lib/data_processing.py` | 每筆 tick 放入實際分鐘；跨分鐘先結算前桶，保留新桶首筆，最後再結算尾桶 |
| `mining_rpt.py` → `DBUtils.db_replace_candle_keys` | 依實際 Date／Time 鍵取代，刪除與插入使用同一連線及交易 |
| 寫入失敗 | rollback，原資料保留 |
| 報表沒有提供的分鐘 | DB 原有資料保留；不推測刪除整個交易時段 |
| 輸入 K 棒空鍵或同鍵多列 | 拒絕，不任選一列 |

分鐘使用結束時間標記：15:17:44 的成交屬於 15:18 K 棒；23:59 的成交歸翌日
00:00。05:00:00／13:45:00 的整點收盤成交歸最後一根，不產生 05:01／13:46。
真正沒有成交的分鐘不補零量 K 棒；亂序 tick 明確拒絕。

既有 DB 未建立全表 UNIQUE，因仍保留待裁決的歷史衝突與異常鍵。

## 驗證標準

僅驗證「parser、DB、匯出三者一致」不足以證明原始成交沒有漏失。
`lib/candle_validation.py` 提供不呼叫 production parser helper 的獨立參考：

1. `read_report_ticks` 獨立讀原始報表，保留每列及出現次數。選取當月單式合約，
   無資料時依現有匯入規則嘗試後續月份，不混入跨月價差單。
2. `reference_candles` 按成交時間獨立分桶，計算每根 OHLCV。
3. `validate_session_candles` 對標準 TX／MTX 夜盤 840＋日盤 300 個分鐘位置驗證：

   ```text
   應有 K 棒根數 = 1,140 - 原始報表零成交分鐘數
   ```

4. 同時要求日期時間鍵唯一、順序正確、每根 OHLCV 全部一致；不是只有根數符合。
5. 再核對 DB 與 day/night/full 匯出、日線 JSON；在臨時 DB 重匯入兩次確認冪等性。

夜盤開始日期與日盤日期由來源決定，可跨假日，不要求相鄰。此處的 1,140 是
標準完整時段的位置數，不是固定要求每份檔案必須有 1,140 列，更不應套用到
沒有同樣夜盤時段的全部歷史資料。

回歸測試包括相同 tick、跨分鐘單筆與多筆、尾筆、非開盤首筆、午夜、收盤整點、
零成交分鐘、跨假日，以及 DB 重跑、非目標保留和失敗 rollback。

```bash
python3 -m unittest discover -s tests -p 'test_candle_storage.py'
python3 -m unittest discover -s tests -p 'test_tick_candles.py'
python3 -m unittest discover -s tests -p 'test_gdrive_logging.py'
python3 -m unittest discover -s tests -p 'test_json_exports.py'
python3 -m unittest discover -s tests -p 'test_foreign_positions.py'
```

測試使用臨時 DB／模擬 Drive，不需要改寫正式資料或上傳報表；執行環境仍需
具備專案 Python 依賴。本次準備提交的上述五組測試共 27 項，已在既有容器環境通過。
